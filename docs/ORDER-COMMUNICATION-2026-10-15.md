# Landed 订单内沟通与版本反馈

## 交互

- 保留当前阶段交付、验收付款。服务可用时，右侧显示订单双方消息，替代邮件表单。
- 钱包签名只登录沟通，不授权转账。后端逐次检查订单双方身份。
- 普通消息用于需求讨论；“沟通修改意见”选择具体阶段 V1/V2，记录对应交付交易。
- 修改反馈不改变合约状态、不暂停验收时间。正式提交和验收仍走原合约。
- 消息发送失败保留当前页面草稿；发送请求用唯一编号避免重复。页面刷新会丢弃未发送草稿，但已保存消息从服务端重新加载。
- 显示发送角色、时间、未读数量，支持更早历史和手动刷新。自动刷新12秒一次。
- 当前只支持文字，链接作为文本显示；文件上传和邮件通知仍未实现。

## 服务与部署

新增 `collaboration-api.js`，通过 Express 同源提供 API，SQLite 持久保存消息和已读位置。无需发币钱包或资金密钥。

运行要求：Node 24+；`COLLAB_ENABLED=true`；准确的 `PUBLIC_ORIGIN`；私有持久化目录 `COLLAB_DATA_DIR`。生产地址必须 HTTPS。数据库不得置于 public/site 或其他公开目录。

GitHub Pages 是静态站，无法运行此服务。静态导出不携带启用标志，仍显示真实可用的邮件备用入口，不显示虚假聊天。

公开部署需要：一台获授权的 Node 服务、持久化磁盘、HTTPS域名及磁盘备份。当前连接的 Railway 账户无已有项目。尚未创建收费资源或公开上传订单消息。应单实例部署；会话和防频繁请求计数在内存中，服务重启需要重新签名。共享NAT下速率限制可能影响演示多人并发。

## 上线检查

- [ ] 用户确认托管环境与费用上限，持久化卷及备份配置。
- [ ] HTTPS域名与 PUBLIC_ORIGIN 一致。
- [ ] 公开部署、两端真实钱包签名、跨设备消息和版本反馈验证。
- [ ] 服务重启后消息仍在，数据库不可公开下载。
- [ ] 磁盘容量、错误监控、用户消息保留/删除政策明确。

当前代码是待部署的测试环境实现，不是已上线服务；不改变链上协议或真实支付规则。
